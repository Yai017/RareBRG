# Towards Bridging Retrieval and LLM Generation in Rare Disease Differential Diagnosis

![Python](https://img.shields.io/badge/Python-3.10%2B-3776AB) ![License: MIT](https://img.shields.io/badge/License-MIT-green)

This repository contains the code of the study, the agent skill that normalizes diagnoses to
MONDO, and the resolution map produced in the experiments. The study splits rare disease
differential diagnosis into diagnosis acquisition and diagnosis reranking, and evaluates on
1,122 RareBench cases with ontology-grounded matching.

## 🧩 Candidate pools

| Pool | Definition | Candidates |
|---|---|---|
| T | Candidate pool from phenotype-driven diagnosis tool | Top 5 of PhenoBrain or PubCaseFinder |
| R | Retrieved candidate pool | Top 5 diseases by ICTO score |
| G | LLM-generated candidate pool | 5 most likely diagnoses generated by an LLM |
| RAG | Candidate pool from retrieval-augmented generation | 5 diagnoses generated with the candidates of R listed in the prompt |
| RUT | The union of R and T | T, with the candidates of R not already in it appended |
| RUG | The union of R and G | G, with the candidates of R not already in it appended |

Diagnosis reranking reorders a pool by ICTO score (retrieval-based reranking, under a margin
gate) or with an LLM (LLM reranking, under a routing gate), the latter in the candidate-only or
the phenotype-grounded setting.

## ⚙️ Installation

```bash
git clone https://github.com/Yai017/RareBRG.git
cd RareBRG
pip install -r requirements.txt
```

LLMs run locally with [Ollama](https://ollama.com) or through the OpenAI, Anthropic and DeepSeek
APIs (with `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` or `DEEPSEEK_API_KEY` set). The models are
listed in `lib/config.py`.

## 📦 Data

```bash
python run.py download      # RareBench and the HPO, HPOA and MONDO releases of the study
python run.py prepare all   # ontology graphs and the MONDO concept table
```

## 🚀 Running the experiments

**1. Retrieval and diagnosis tools**

```bash
python run.py retrieve      # retrieval: pool R
python run.py tools fetch   # query the PhenoBrain and PubCaseFinder web services
python run.py tools map     # map their identifiers to MONDO: pools T
```

**2. LLM generation**, for each LLM of the study (`llama3.1-8b`, `qwen3.5-9b`, `phi4-14b`,
`gemma4-12b`, `opus-4.8`)

```bash
python run.py generate -m qwen3.5-9b   # pools G and RAG
```

**3. Diagnosis normalization**, for each LLM and for the tools (`--tools`)

```bash
python run.py normalize -m qwen3.5-9b   # map lookup, literal matching, SapBERT candidates
```

If it reports names left for agent matching, resolve them as described in
[Diagnosis normalization](#diagnosis-normalization) before step 4.

**4. LLM reranking and scoring**

```bash
python run.py rerank -m qwen3.5-9b     # LLM reranking of G, RUG and RAG
python run.py rerank -m opus-4.8 -p R  # LLM reranking of R
python run.py score                    # Table 1
```

`score` also computes retrieval-based reranking and the gates.

## 🏷️ Diagnosis normalization

Each diagnosis is normalized to a MONDO concept, or marked invalid, by the concept resolution
pipeline of the study:

1. **Resolution map**: a free-text name is looked up in `data/resolution_map.json`, and a tool's
   encoded identifier in MONDO's cross-references. The map holds the 15,391 names of the study: the
   15,382 that the LLMs generated and 9 more from tool candidates whose identifiers MONDO does not
   cross-reference.
2. **Literal matching**: a name not found in the map is matched against MONDO labels and synonyms.
3. **Agent matching**: for each name still left, a coding agent with the
   [diagnosis-normalize skill](skills/diagnosis-normalize/SKILL.md) selects among its SapBERT top-5
   MONDO candidates or searches MONDO further, and a second agent audits each verdict.
4. **Cross-check**: each verdict is checked against MONDO and added to the resolution map.

`python run.py normalize` runs the resolution map and literal matching. If it reports names left,
resolve them with a coding agent:

1. Set up once:
   - `pip install torch transformers`
   - `python run.py prepare sapbert-index`
   - copy `skills/diagnosis-normalize` into the skills folder of your coding agent (`.claude/skills/`
     for Claude Code)
2. Run `python run.py normalize -m <model>` (or `--tools`) with this setup in place. It writes the
   names left, with their SapBERT top-5 candidates, as batches to `skills/diagnosis-normalize/workdir/batches/`.
3. Ask the agent, for example, *"Run the diagnosis-normalize skill on the qwen3.5-9b batches."* It
   carries out agent matching and the cross-check, running `python run.py normalize --apply` itself,
   until every name is decided.
